📋 第 4 题：关系数据库 ERD 建模与 SQL 核心查询实战

📌 【情境材料】
某独立中学图书馆正在对“图书借阅管理系统”的后台数据库进行规范化设计与性能重构。

问题：
  1. 1. 在概念数据模型中，一个读者可以借阅多本不同的图书，一本图书在不同时间段也可被多位读者借阅。因此“读者”与“图书”在逻辑上属于何种基数关联（Cardinality）？在关系数据库建表中，为了消除数据冗余与操作异常，系统设计人员是如何通过【借阅记录】表将其消除的？（3分）

🎯 官方参考答案要点与阶梯采分点
🎯 官方标准参考答案
1. 基数关联与消除手段（3分）：
• 基数关联：多对多关联（M:N / Many-to-Many）（1分）；
• 消除手段：在关系数据库物理建模中，通过引入一个联结实体（Associative Entity / 联结表）——即【借阅记录】表，将其拆解为两个“一对多（1:N）”的关联（即“读者 1 : N 借阅记录”与“图书 1 : N 借阅记录”），在借阅表中分别设置两个外键指向读者与图书的主键，从而彻底消除数据冗余与更新异常（2分）。
2. 标准单表过滤与排序 SQL（3分）：
🗄️ SQL 结构化查询语言脚本SQL
   SELECT Reader.name AS 姓名, COUNT(Borrow_Record.record_id) AS 借书总数
   FROM Reader
   JOIN Borrow_Record ON Reader.reader_id = Borrow_Record.reader_id
   GROUP BY Reader.reader_id, Reader.name
   HAVING COUNT(Borrow_Record.record_id) >= 5;
• （评分标准：SELECT 与 FROM 正确给1分；WHERE 双条件正确给1分；ORDER BY price DESC 降序给1分）。
3. 多表联结、分组聚合与筛选 SQL（4分）：
🗄️ SQL 结构化查询语言脚本SQL
   SELECT Reader.name AS 姓名, COUNT(Borrow_Record.record_id) AS 借书总数
   FROM Reader
   JOIN Borrow_Record ON Reader.reader_id = Borrow_Record.reader_id
   GROUP BY Reader.reader_id, Reader.name
   HAVING COUNT(Borrow_Record.record_id) >= 5;
• （评分标准：多表 INNER JOIN 或 WHERE 关联正确给1分；GROUP BY 读者分组给1分；COUNT 聚合给1分；HAVING 筛选条件正确给1分）。

📋 第 5 题：智慧校园综合网络安全加固与勒索攻击应急响应
满分 10 分
📌 【情境材料】
某知名私立独中在期末考试前夕遭遇了一次严重的网络安全危机：
学校数据中心的核心教务学籍数据库与财务缴费服务器被黑客植入了新型勒索软件，核心 .mdf 数据库文件全部被高强度 AES-256 算法加密，黑客索要 3 个比特币方可提供解密私钥。
事后由国家网络安全专家团队介入调查，确认了黑客的完整渗透攻击链条：
- 第 1 阶段：黑客通过社会工程学手段，伪装成校友向多名教职工发送携带免杀木马附件的钓鱼邮件，一名职员在办公电脑上点击运行了附件宏代码，导致其办公机沦为肉鸡；
- 第 2 阶段：黑客以该受控办公机为跳板，在内网发起端口扫描，发现机房 Linux 核心数据库服务器的 SSH 22 端口暴露在内网，且允许使用弱口令明文密码登录；
- 第 3 阶段：黑客利用字典爆破成功登入 Linux 数据库服务器，不仅加密了本地数据库，还通过内网自动挂载脚本将同一网段内 NAS 存储设备上的每日增量备份文件一并加密销毁。
问题：
  1. 1. 针对黑客渗透的第 1 阶段（钓鱼邮件与宏病毒木马），学校应从技术拦截与全员安全意识管理两个维度，各提出一项具体的防范措施。（2分）
  2. 2. 针对第 2 阶段中 Linux 服务器的远程维护漏洞，请给出两项针对 SSH 服务的专业安全加固配置方案。（2分）
  3. 3. 针对第 3 阶段中“本地数据与网络存储备份一并被加密”的惨痛教训，请完整写出资讯安全领域推崇的“3-2-1 备份黄金法则”的具体要求，并解释为何物理隔离（Air-Gapped 离线备份）能够有效抵御此类勒索攻击。（3分）
  4. 4. 从现代企业与智慧校园网络防御哲学出发，阐述“零信任架构（Zero Trust Architecture）”的核心设计原则（至少列举两条核心原则），并说明零信任架构如何能有效遏制黑客在内网的“横向移动渗透”（Lateral Movement）。（3分）

🎯 官方标准参考答案
1. 钓鱼宏病毒的技术拦截与意识管理（2分，各1分）：
• 技术拦截措施：在校园邮件网关部署防钓鱼与沙箱检测系统，在终端办公电脑上强制通过组策略默认禁用所有 Office 文档的 VBA 宏自动运行，拦截未知可执行文件；
• 安全意识管理：建立全员网络安全红线规范，定期开展实战化钓鱼邮件演练，要求员工对任何索要凭证或含附件的陌生邮件严格落实“离线多渠道核验”，绝不随意点击。
2. 两项 SSH 专业安全加固方案（2分，各1分）：
① 强制禁用密码登录，全面推行高强度 SSH 密钥对（Key-pair）认证：在 sshd_config 中配置 PasswordAuthentication no，彻底封死字典暴力破解入口；
② 更改默认 22 端口并限制源 IP 访问：将 SSH 端口更改为自定义高位端口，并配合防火墙配置仅允许特定内网运维跳板机（Bastion Host）或 VPN IP 发起连接。
3. 3-2-1 备份黄金法则与物理隔离优势（3分）：
• 3-2-1 备份法则具体要求（2分）
• 3：保留至少 3 份 完整数据副本（1 份生产数据 ＋ 2 份备份）；
• 2：存放在至少 2 种 不同的物理介质上（例如：本地磁盘阵列 NAS ＋ 磁带/离线移动硬盘）；
• 1：至少保证有 1 份 副本存放在异地或处于物理隔离（Air-Gapped 离线断网）环境中。
• 物理隔离抵御勒索的核心优势（1分）：黑客通过网络渗透能够加密所有挂载在内网的在线存储（如 NAS/云盘）；而物理隔离的冷备份介质（如拔下网线的离线磁带或外部硬盘）与网络在物理层面完全断开，黑客的恶意加密脚本在物理上传输不可达，从而确保备份数据绝对不会被感染。
4. 零信任架构核心原则与遏制横向移动（3分）：
• 两条核心设计原则（2分，各1分）
① 持续验证，永不信任（Never Trust, Always Verify）：无论是来自内网还是外网的访问请求，默认均不予信任，必须基于身份、设备环境与行为进行持续动态认证；
② 最小权限原则（Least Privilege）：仅授予主体完成当前任务所必需的最小访问权限，严格实施基于角色的微隔离（Micro-segmentation）。
• 遏制横向移动机理（1分）：在传统边界安全模型下，黑客一旦突破一台办公机即对整个内网畅通无阻；而在零信任架构下，网络被细分为无数微隔离区域，办公机访问数据库服务器必须经过独立的身份令牌与策略检查，受控终端因缺乏合法凭据无法随意扫描和连接其他内网服务器，从而将攻击范围严格限制在单点受害者以内。
