📋 第 1 题：实体关系图（ERD）数据建模与范式优化
满分 10分
📌 【情境材料】
某独中校友会计划开发一套全新的“校友管理与捐款追溯系统”，用于记录历届校友的联络档案、校友参与的各届联谊聚会以及向母校爱心捐款的流向。
经过系统分析师的前期业务调研，提取出以下核心业务规则：
  1. 1. 校友（Alumnus）：包含校友编号（主键）、姓名、毕业年份、联络手机、电子邮件；
  2. 2. 捐款项目（Donation_Project）：包含项目编号（主键）、项目名称（如“大礼堂修缮基金”、“清寒助学金”）、目标筹款金额；
  3. 3. 捐款记录（Donation_Record）：记录每一笔爱心捐款，包含捐款流水号（主键）、捐款金额、捐款日期、支付方式；
  4. 4. 业务关联：
    - 一位校友可以向多个不同的捐款项目进行多次捐款，也可以暂不捐款；
    - 一个捐款项目可以接受来自多名不同校友的多笔捐款；
    - 每一笔具体的【捐款记录】必定且只能对应一位具体的校友，并指定流向一个具体的捐款项目。
    问题：
  5. 1. 在数据库概念设计中，“校友”实体与“捐款项目”实体之间在业务上构成了何种实体基数关联（Cardinality，即 1:1、1:N 还是 M:N）？在关系数据库的物理建表中，为了有效消除该多对多关联引起的数据冗余与插入异常，系统分析师通常采用什么设计手段？（3分）
  6. 2. 请为联结两者的核心实体【捐款记录】设计其规范的数据库表属性字段，明确指出该表的主键（Primary Key, PK）以及该表所包含的两个外键（Foreign Keys, FK）。（3分）
  7. 3. 假设一名实习程序员在设计【校友】表时，将字段设计为：校友编号, 姓名, 毕业年份, 联络手机, 工作单位名称, 工作单位所在城市, 工作单位办公电话。
    已知“工作单位所在城市”和“工作单位办公电话”完全依赖于“工作单位名称”，而与“校友编号”仅构成传递依赖关系。
    - 请指出该设计违反了关系数据库的哪一范式（Normal Form）？（2分）
    - 请简述应如何拆分重构该表，使其满足更高层级的规范化范式要求。（2分）
🎯 官方参考答案要点与阶梯采分点
🎯 官方标准参考答案
1. 实体关联类型与物理消除手段（3分）：
• 实体基数关联：多对多关联（M:N / Many-to-Many）（1分）；
• 消除手段：在关系模型中，严禁直接在两实体间建多对多表。系统分析师通过引入一个联结实体（Associative Entity / 联结表 / 交叉表）——即【捐款记录】表，将其成功拆解为两个“一对多（1:N）”的关联（即校友 1 : N 捐款记录，捐款项目 1 : N 捐款记录），从而彻底消除数据冗余与操作异常（2分）。
2. 【捐款记录】表属性字段与主外键设计（3分）：
• 主键（PK）：捐款流水号（或 Donation_ID）（1分）；
• 外键一（FK1）：校友编号（引用【校友】表主键）（1分）；
• 外键二（FK2）：项目编号（引用【捐款项目】表主键）（1分）。
• （核心字段清单：捐款流水号 [PK], 校友编号 [FK], 项目编号 [FK], 捐款金额, 捐款日期, 支付方式）。
3. 范式违背判定与拆分优化（4分）：
• 违反的范式：违反了第三范式（3NF / Third Normal Form）（2分）。（理由：3NF 要求消除非主属性对主键的传递函数依赖。此处 校友编号 -> 工作单位名称 -> (工作单位所在城市, 工作单位办公电话) 构成了典型的传递依赖）；
• 拆分重构方案：将单表拆分为两张独立的规范化关系表（2分）：
① 【校友表】：校友编号 [PK], 姓名, 毕业年份, 联络手机, 工作单位编号 [FK]；
② 【工作单位表】：工作单位编号 [PK], 工作单位名称, 工作单位所在城市, 工作单位办公电话。

📋 第 2 题：网络传输性能计算、带宽延迟积与 QoS 保障
满分 10分
📌 【情境材料】
某独中总校与分校之间租用了一条专用的点对点千兆数据链路，带宽容量标称为 C = 1 Gbps（即 10⁹ bps）。
经网络测试仪器测量，该两校之间的网络单向物理传播延迟（Propagation Delay）为 t_p = 10 毫秒（即 10 ms = 0.01 秒）。
问题：
  1. 1. 带宽延迟积（BDP / Bandwidth-Delay Product）计算：
    在网络工程中，带宽延迟积 BDP = 带宽 × 单向传播延迟，代表该链路上在任意时刻能够容纳的正在空中飞行的最大数据量（网络管道容量）。
    请写出详细的单位转换与计算推导过程，计算该专用数据链路的带宽延迟积（以位元 bit 和兆字节 MB 为单位表示，按十进制 1 MB = 10⁶ Bytes 或二进制 1024² 换算均可）。（4分）
  2. 2. 大文件传输理论推导：
    两校机房管理员计划在深夜通过该专线同步一个大小为 12 GB 的全校虚拟机镜像文件。
    若网络传输协议与链路的实际利用效率为 80\%（即实际有效传输速率为标称带宽的 80\%）：
    请写出计算步骤，求传输完成该虚拟机镜像文件所需的理论净传输时间（单位：秒，保留至整数）。（3分）
  3. 3. QoS（服务质量）策略制定：
    在白天正常教学时间内，由于两校间同时进行跨校区高清远程互动视频直播教学以及普通教职员的日常大文件下载，导致远程直播课堂频繁卡顿。
    请简述何谓网络中的 QoS（Quality of Service）技术，并提出一项具体的交换机/路由器排队调度配置策略，以确保远程视频教学的绝对流畅。（3分）
🎯 官方参考答案要点与阶梯采分点
🎯 官方标准参考答案
1. 带宽延迟积（BDP）计算推导（4分）：
• 公式：BDP = 带宽 C × 单向时延 t_p（1分）
• 推导步骤（以位元 bit 为单位）

BDP = 1 Gbps × 10 ms = 10⁹ bps × 0.01 s = 10,000,000 bits = 10⁷ bits（1分）

• 单位换算为兆字节（MB）
• 若采用十进制单位制（网络标准）：

BDP = (10,000,000 bits ÷ 8 × 10⁶) = (10⁷ ÷ 8 × 10⁶) MB = 1.25 MB（2分）

• 若采用二进制计算机存储单位制（1024²）：

BDP = (10,000,000 ÷ 8 × 1024 × 1024) ≈ 1.192 MB（同样给予满分）。

2. 大文件理论传输净时间计算（3分）：
• 步骤一：计算有效传输速率

有效带宽 = 1 Gbps × 80\% = 0.8 Gbps = 800 Mbps = 800,000,000 bps（1分）

• 步骤二：转换文件容量为位元

12 GB = 12 × 10⁹ × 8 = 9.6 × 10¹⁰ bits

（若按二进制标准：12 × 1024³ × 8 = 103,079,215,104 bits）；

• 步骤三：计算所需传输时间

T = (9.6 × 10¹⁰ bits ÷ 8 × 10⁸ bps) = 120 秒

（若按二进制标准计算：T = (103,079,215,104 ÷ 800,000,000) ≈ 128.85 秒 ≈ 129 秒。两者推导均按满分 2分 计）。

答：传输该虚拟机镜像文件理论上需要约 120 秒（或 129 秒）。

3. QoS 概念与排队调度策略（3分）：
• QoS 概念：QoS（服务质量）是网络中用于针对不同应用的数据流提供不同优先级控制的技术，确保关键、敏感业务（如视频/语音）获得低延迟、低抖动与带宽保障（1分）；
• 具体排队配置策略：在路由器/交换机上配置优先排队（Priority Queuing, PQ）或基于类的加权公平排队（CBWFQ）策略：将远程互动教学的视频/语音数据流打上高优先级 DSCP/CoS 标签，划入最高优先级队列（Priority Queue）绝对优先放行；将日常大文件下载流量限速并置入低优先级尽力而为（Best Effort）队列（2分）。

评分维度优秀（Full / 9-10分）良好（Good / 7-8分）基础（Basic / 4-6分）待改进（Poor / 0-3分）
BDP 推导与单位换算（4分）公式、代入过程清晰无误，bit 与 MB 两种单位转换极其工整。公式正确，但在 Byte 与 bit 转换处有计算微小笔误（扣1分）。仅写出公式，未完成代入计算。完全不懂 BDP 含义，乱列算式。

📋 第 3 题：OS 进程调度算法分析与甘特图甘特时序推导
满分 10分
📌 【情境材料】
某单核心 CPU 计算机操作系统中，就绪队列（Ready Queue）在零时刻依次迎来了三个并发执行的用户进程 P_1, P_2, P_3。
各进程的到达时间（Arrival Time）与所需的 CPU 运行服务时间（Burst Time）如下表所示：
| 进程名称 | 到达时间（ms） | CPU 服务时间（ms） | 优先级（数值越小优先级越高） |
| :---: | :---: | :---: | :---: |
| P_1 | 0 | 8 | 3 |
| P_2 | 1 | 4 | 1 |
| P_3 | 2 | 2 | 2 |
问题：
  1. 1. 假设操作系统采用非抢占式先来先服务算法（FCFS / First-Come, First-Served）：
    - 请按时序写出各进程的执行次序及各自的完成时间点；（2分）
    - 请计算在此调度策略下，三个进程的平均等待时间（Average Waiting Time）。（2分）
  2. 2. 假设操作系统采用非抢占式最短作业优先算法（SJF / Shortest Job First）：
    - 请注意 P_1 在时刻 0 到达并立即上 CPU 执行。请推导在时刻 8 当 P_1 执行完毕后，系统将优先调度哪一个进程执行？并写出最终的执行顺序；（2分）
    - 计算非抢占式 SJF 算法下，三个进程的平均周转时间（Average Turnaround Time）。（2分）
  3. 3. 在采用时间片轮转算法（RR / Round Robin）时，时间片（Time Slice / Quantum）的大小设定对系统性能至关重要。请分别简述：
    - 若时间片设定过大（趋于无穷大），算法将退化为何种算法？（1分）
    - 若时间片设定过小（如微秒级），会对操作系统整体运行效率造成什么严重负面后果？（1分）
🎯 官方参考答案要点与阶梯采分点
🎯 官方标准参考答案
1. 非抢占式 FCFS 调度推导（4分）：
• 执行时序：进程严格按到达时间调度：P_1 → P_2 → P_3（1分）。
• P_1：时刻 0 开始执行，服务 8 ms，完成时间为 8 ms；
• P_2：时刻 8 开始执行，服务 4 ms，完成时间为 12 ms；
• P_3：时刻 12 开始执行，服务 2 ms，完成时间为 14 ms（1分）。
• 等待时间计算：等待时间 = 开始执行时间 - 到达时间（或 周转时间 - 服务时间）：
• P_1 等待时间 = 0 - 0 = 0 ms；
• P_2 等待时间 = 8 - 1 = 7 ms；
• P_3 等待时间 = 12 - 2 = 10 ms；
• 平均等待时间：= (0 + 7 + 10 ÷ 3) = (17 ÷ 3) ≈ 5.67 ms（2分）。
2. 非抢占式 SJF 调度推导（4分）：
• 执行时序
• 时刻 0 只有 P_1 到达，由于非抢占，P_1 必须持续运行直到完成（0 ~ 8 ms）；
• 时刻 8 时，P_2（剩余 4 ms）与 P_3（剩余 2 ms）均已在就绪队列中。非抢占 SJF 选择服务时间最短的进程，因此优先调度 P_3，最后调度 P_2（1分）；
• 完整执行顺序：P_1 (0 \sim 8) → P_3 (8 \sim 10) → P_2 (10 \sim 14)（1分）。
• 周转时间计算：周转时间 = 完成时间 - 到达时间：
• P_1 周转时间 = 8 - 0 = 8 ms；
• P_3 周转时间 = 10 - 2 = 8 ms；
• P_2 周转时间 = 14 - 1 = 13 ms；
• 平均周转时间：= (8 + 8 + 13 ÷ 3) = (29 ÷ 3) ≈ 9.67 ms（2分）。
3. 时间片轮转（RR）极端情况分析（2分，各1分）：
• 时间片设定过大：当时间片大于所有就绪进程的最大服务时间时，每个进程上 CPU 都能一次性运行完毕，算法将完全退化为先来先服务算法（FCFS）（1分）；
• 时间片设定过小：会导致 CPU 在不同进程之间产生极其频繁的上下文切换（Context Switch），保存与恢复寄存器等额外开销激增，CPU 大部分算力被调度管理浪费，整体系统吞吐量严重急剧下滑（1分）。

评分维度优秀（Full / 9-10分）良好（Good / 7-8分）基础（Basic / 4-6分）待改进（Poor / 0-3分）
FCFS 时序与等待时间（4分）完成时间点与各等待时间计算毫无瑕疵，公式清晰，除法精确。时序正确，但等待时间均值存在微小算术错误（扣1分）。混淆了等待时间与周转时间。时序安排错误。

📋 第 4 题：跨平台网络通讯协议分层与服务架构实战
满分 10分
📌 【情境材料】
某企业搭建了一套基于微服务架构的“智能物联资产巡检系统”。
在设备机房内，数十台基于 Linux 嵌入式系统的传感器巡检小车通过 Wi-Fi 将采集到的温度、振动数据通过 MQTT/HTTP 协议上报至企业私有云端的 Docker 容器中。
云端后台数据库运行在 Linux 伺服器上，而企业管理人员在办公室内使用搭载 Windows 11 操作系统的笔记本电脑通过浏览器查看巡检大屏与下发控制指令。
问题：
  1. 1. 在网络通信中，Linux 传感器设备与 Windows 管理终端能够跨越不同的 CPU 硬件架构与不同的操作系统实现无缝数据交互。这主要依赖于计算机网络通信的什么核心机制？请结合协议分层（OSI 或 TCP/IP）思想进行简要阐明。（3分）
  2. 2. 当传感器小车向云端伺服器发送一条告警数据时，在网络协议栈的传输过程中，数据在发送端自顶向下依次会经历“数据封装（Encapsulation）”过程。
    请简述从应用层数据开始，传输层、网络层和数据链路层分别在原始数据前面添加了什么控制信息（头部 Header），从而将数据组装成了什么格式的协议数据单元（PDU）？（3分）
  3. 3. 在物联网设备与云平台通信中，MQTT 协议相较于传统的 HTTP 协议被公认为更适合低功耗、弱网环境下的嵌入式设备。请从报文头部开销与通信交互模式（如请求响应 vs 发布订阅）两个技术维度，各说明一项 MQTT 协议的显著优势。（2分）
  4. 4. 为确保云端 Linux 伺服器的网络访问安全，网络管理员需要在服务器上配置基于 SSH（安全外壳协议）的远程运维。

1. 跨平台互联核心机制与分层思想（3分）：
• 核心机制：依赖于标准化的开放网络通信协议族（如 TCP/IP 协议族）（1分）；
• 分层思想阐明：协议分层实现了“对等层透明通信”与“屏蔽底层异构细节”。无论底层硬件采用何种指令集（ARM 或 x86）、无论操作系统是 Linux 还是 Windows，只要双方在相同的网络层遵循标准 IP 寻址、在传输层遵循标准 TCP 握手规范，底层操作系统的系统调用差异就被协议栈完全封装隐藏，从而实现真正无缝的跨平台交互（2分）。
2. 协议栈数据封装（Encapsulation）全流程（3分，各1分）：
• 传输层（Transport Layer）：在原始数据前添加 TCP 或 UDP 头部（包含源端口与目的端口号等控制信息），组合封装成数据段（Segment）或数据报（Datagram）；
• 网络层（Network Layer）：在传输层数据段前添加 IP 头部（包含源 IP 地址与目的 IP 地址等寻址信息），组合封装成 IP 数据包 / 分组（Packet）；
• 数据链路层（Data Link Layer）：在 IP 数据包前后分别添加帧头（Frame Header，包含源与目的 MAC 地址）与帧尾（Frame Trailer，包含 FCS 循环冗余校验码），组合封装成数据帧（Frame）。
3. MQTT 协议相较于 HTTP 的两项显著优势（2分，各1分）：
• 报文头部开销极小：HTTP 报文头部庞大（通常包含数百字节甚至几 KB 的文本 Headers），而 MQTT 固定头部最小仅有 2 字节，在弱网与低带宽环境下极大节约网络流量与设备电量；
• 发布/订阅（Pub/Sub）解耦模式：HTTP 是传统的单向“客户端请求-服务端响应”短连接轮询模式；而 MQTT 基于轻量级的“发布者-代理服务器-订阅者”模式，设备与 Broker 保持长连接心跳，伺服器可即时向海量设备毫秒级推送指令，实现高度松耦合与低延迟通信。
4. SSH 协议配置与密钥对认证优势（2分，各1分）：
• 传输层协议与端口号：基于 TCP 协议，默认使用 22 端口（0.5分）；
• SSH 密钥对登录的核心安全优势
① 彻底免疫密码字典攻击与暴力破解：公私钥基于非对称高强度加密（如 RSA 4096 位或 Ed25519），私钥存留在管理员本地绝不网络传输，黑客即便穷举也无法攻破；
② 从源头上消除密码明文网络泄露与弱口令隐患，配合禁用伺服器密码登录配置后，安全性显著提升（1.5分）。
